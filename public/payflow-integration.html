PayFlow

Provider-agnostic, multi-tenant payment infrastructure for e-commerce merchants: pay-in through a PSP (Cashfree), a double-entry ledger, merchant wallets, pay-outs to merchant bank accounts, webhooks, retries and reconciliation.

Merchant PortalAdmin & Reconciliation

1. Onboard

POST /v1/merchants
{ "businessName": "Demo Store", "ownerName": "Demo Owner", "email": "merchant@example.com" }
-> { "credentials": { "merchantId": "mer_…", "apiKey": "pk_test_…" } }   (shown once; only its hash is stored)

2. Collect a payment

POST /v1/payments
Authorization: Bearer pk_test_…
Idempotency-Key: order-1001

{ "amount": 99900, "orderId": "order-1001",
  "customer": { "phone": "9876543210", "email": "buyer@example.com" } }

-> 201 { "paymentId": "pay_…", "status": "PENDING",
         "checkout": { "url": "https://…/checkout?payment=pay_…", "type": "cashfree", "paymentSessionId": "session_…" } }

Send the customer to checkout.url (or open Cashfree's JS SDK with paymentSessionId). Card/UPI details are entered on the PSP's page only. The payment becomes SUCCESS when the PSP's signed webhook arrives. Only then are the ledger and wallet updated. Poll GET /v1/payments/:id or rely on your own flow. Amounts are integer paise.

States: CREATED → PENDING → SUCCESS | FAILED | CANCELLED | EXPIRED; a customer may retry a failed attempt on the same order (FAILED → SUCCESS); SUCCESS → REFUNDED; amount mismatches go to MANUAL_REVIEW.

3. Register a payout account, then withdraw

POST /v1/merchant/payout-account
{ "name": "Demo Owner", "accountNumber": "026291800001191", "ifsc": "YESB0000262" }

POST /v1/payouts
Idempotency-Key: payout-1001
{ "amount": 50000, "mode": "IMPS" }
-> 201 { "payoutId": "po_…", "status": "PROCESSING" }   → SUCCESS (with UTR) via the payout provider's webhook

States: CREATED → PROCESSING → SUCCESS | FAILED, SUCCESS → REVERSED; unconfirmable transfers go to MANUAL_REVIEW with funds kept reserved.

4. Balances, ledger, reconciliation

GET /v1/wallet                    available / pending (paise)
GET /v1/ledger                    double-entry entries
GET /v1/reconciliation            wallet vs ledger accounts, all transactions balanced
GET /v1/reconciliation/provider   every payment/payout vs the PSP's own record

With PAYMENT_PROVIDER=simulator the same API runs offline against a built-in PSP simulator that emits signed webhooks; no real money moves.
